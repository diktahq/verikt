## v0.3.0 — 2026-11-27

Issues #8 to #18, then #21, #23, #24, #28, #29, #30 and #32, then the findings of a
three-lens review of this release (red team, security, agent safety; #36). Most are cases
where verikt reported success for something it had not done: an installer that skipped
verification when it could not verify, a hook that never reported a violation, scaffolds
that failed their own `verikt check`. **Read the upgrade notes first:** several change what
an existing pipeline sees.

### Upgrade notes

**An unavailable engine stops `verikt check`, and the error says why.** If the embedded
engine cannot be extracted, the check fails with `analysis engine unavailable` and the
underlying cause. `--allow-degraded` skips the built-in detectors instead, with a warning on
stderr, and checks only proxy rules and decision gates. It is refused with `--detectors`,
which would leave nothing to check.

**`--diff` and `--staged` see more files.** They now include renamed files, and `--diff`
includes files git does not track yet, compares paths relative to the checked project (so it
works in monorepos), and reads non-ASCII file names verbatim. Findings these filters used to
drop now appear, so a pipeline gating on `--diff main` can newly fail with no change to your
code.

**Two new structure detectors, both at warning severity.** `live_dot_claude_fixture` is
always on and reports a `.claude/` directory holding `rules/` or `skills/` under a test or
fixture path, or a standalone `CLAUDE.md` or `CLAUDE.local.md` in a fixture case. Claude Code
loads these on demand when it works on a file there, so an agent working on the fixture takes
them as live instructions. `cmd_allowlist` (Go) reports any `package main` under `cmd/` or at
the module root that `check.allowed_entrypoints` does not name, and is off until you set that
key. Waive a finding with `severity_overrides` under the detector's name (`severity: ignore`,
a `reason`, and `paths`), or make one blocking with `severity: must`.

**Two new checks read CI, script and container files, both at warning severity** and on for
every project. `silent_ci_swallow` reports `continue-on-error: true` in GitHub workflows and
`|| true`, `|| :` or `|| exit 0` that hides a failed test, lint, check or migration.
`mutable_install_url` reports `curl | sh`, `/releases/latest/download/`, branch-pinned
`raw.githubusercontent.com` URLs and workflow `uses:`, and untagged or `:latest` Dockerfile
images. A `PostToolUse` hook written by an older `verikt guide` is reported; re-run
`verikt guide` to replace it. Accept one line with `# verikt:allow <rule> reason="..."` on it
or directly above it; a malformed marker allows nothing and is reported as
`invalid_allow_directive`.

**Cursor's rules moved to `.cursor/rules/verikt.mdc`.** Cursor deprecated `.cursorrules`.
The next `verikt guide` moves verikt's section out of `.cursorrules`, keeps your own content
there, and deletes the file only if verikt's section was all it held. Commit the new file,
along with `AGENTS.md` if you use it and the new `.verikt/references/` directory that every
agent file now points to. Without that directory, the agent is sent to files that don't
exist.

**Claude Code rule files use `paths:` frontmatter.** Claude Code ignores `globs:`, so every
`verikt-<category>.md` loaded in every session. Category files now load when Claude works on
a matching path. `verikt guide` removes generated `verikt*.md` files the current run did not
write; files without verikt's generated header are never touched.

**`verikt guide` refuses symlinks**, naming the path, when a file it writes or reads or a
directory above it inside the project is a symlink. `verikt guide --catalog-only` refuses in a
project with `verikt.yaml`; it used to delete `.verikt/references/architecture.md` and strip
the layer rules from every target.

**`verikt check` validates `severity_overrides` and `check.allowed_entrypoints` before it
runs.** An override severity must be `must`, `should` or `ignore`, and `ignore` needs a
`reason`. `severity: info` used to turn an error into a finding that passed even under
`--strict`; it now stops the check with a message naming the entry.

**Grep rules mean what the docs say.** The Rust engine reported the compliant line or file for
`must-contain`, `must-not-contain` and `file-must-contain` and missed the violating one. A
proxy rule that relied on that, typically `must-not-contain` used to exclude lines, now
reports the lines it skipped: rewrite it with `must-contain`. A proxy rule with no `severity`
is an error, as documented; the engine ran it as `info`.

**Waivers stay visible.** A `# verikt:allow` marker lists the finding under WAIVED with its
reason instead of hiding it, and waivers are kept under `--diff` and `--staged`.

**The engine cache must be private.** verikt stops instead of running the engine when its
cache directory or the `engine-<hash>` directory inside it is a symlink, not a directory,
group- or world-writable, or owned by another user. verikt has always created them as `0700`,
so only a hand-made or shared cache is affected. `sudo verikt` with a cache owned by your user
is refused for the same reason.

**Projects scaffolded with an earlier version keep their old components.** Clean and layered
projects were given hexagonal components and failed their own check, and `platform/` packages
were orphans in every architecture. Copy `components`, `rules.structure.required_dirs` and
`check` from a fresh `verikt new --arch <your arch>`. The new `app` component covers `cmd/`
and `internal/bootstrap/`, so `check.exclude: [cmd/**]` can go.

**Generated HTTP code changed shape.** Earlier scaffolds keep working; this matters when you
copy code from a new scaffold or run `verikt add` against an old one.
`NewRouter(logger)` is now `NewRouter(logger, timeouts, registerAPI)`, with JSON routes inside
a request-timeout group and streaming routes outside it. `NewHTTPServer` takes `timeouts` and
sets read, header, write and idle timeouts from `http.read_timeout` and `http.write_timeout`
in `config.yaml`. sse's `SSEHandler` is replaced by `NewSSEHandler(keepAlive)` at `/events`;
websocket's hub is at `/ws`.

**WebSocket upgrades are same-origin.** The websocket template accepted every `Origin`, which
let any site open a connection with a signed-in user's cookies. A browser client on another
origin is refused until you set `CheckOrigin` to an allow-list.

**`bff` requires `bootstrap`.** Without it the generated gateway was never served.
`verikt new` and `verikt add bff` add `bootstrap` and `platform` for you, but `verikt add`
never overwrites files: in an existing project, make `cmd/<name>/main.go` call
`bootstrap.Run(version)`. Backends come from `BFF_SERVICES` and endpoints from `Routes()`,
which is empty, so the gateway serves nothing until you declare a route.

**`go.mod` targets the Go version verikt detects**, instead of always `go 1.22`:
`--set GoVersion` when given, else the installed toolchain's major.minor, else `1.22`. A project
scaffolded on Go 1.26 says `go 1.26`, which older toolchains refuse to build; pass
`--set GoVersion=<older>` to target them. `verikt add` uses the version in the project's
`go.mod`.

**Generated security defaults changed (new projects and `verikt add` only).** Existing
generated code is not rewritten. `middleware.RealIP` is gone from the router;
`decodeJSON(w, r, dst)` caps bodies at 1 MiB; `RateLimiter(ctx, rps, burst, logger)` stops
with `ctx` and tracks at most 100,000 clients; `Idempotency(store, scope, logger)` scopes
replays to the caller, method and path; `Tenant(resolver)` resolves the tenant from verified
auth and starts with `tenant.NotConfigured`, which refuses every request until you replace it;
oauth2's `HandleOAuth2Callback` is replaced by `OAuth2Flow`; CORS panics at startup on `*`
with credentials; `docker-compose.yml` publishes ports on `127.0.0.1` only.
`verikt add rate-limiting` in a project that pins chi older than v5.5.0 needs
`go get github.com/go-chi/chi/v5@latest` before it compiles.

**No Windows archives, and installing no longer runs `verikt setup`.** The Windows build
shipped without the engine, so `verikt check` could only fail there. Releases are macOS and
Linux, amd64 and arm64. Neither Homebrew nor the install script registers verikt with your
agents any more: run `verikt setup`, or pass `--setup` to the script.

### Added

**An `AGENTS.md` target** (`verikt guide --target agents`) for Codex, Antigravity and other
agents that read it. verikt writes only its own marked section.

**A two-tier guide.** The always-loaded file for each agent stays within 30 instructions and
1,500 tokens, enforced by tests on every target. Layer detail, the capability catalog and
the review checklist moved to `.verikt/references/`, which the agent reads when a task
calls for them.

**`verikt setup --codex` and `--antigravity`**, opt-in, writing a marked section of
`~/.codex/AGENTS.md` or `~/.gemini/GEMINI.md`. These paths are not yet checked against the
vendors' documentation (#19).

**`verikt check --strict` and `check.fail_on: warning`** make warning-severity findings fail
the check, across built-in detectors, anti-patterns, proxy rules and decision gates. Without
either, warnings still pass. The last line of output gives the counts, the verdict and the
reason, and `-o json` adds `fail_on` and per-severity counts.

**`silent_ci_swallow`, `mutable_install_url`, `cmd_allowlist` and `live_dot_claude_fixture`**,
all at warning severity (see the upgrade notes). Running the first two over verikt's own
templates found the GitLab CI and devcontainer templates piping golangci-lint's `install.sh`
from `master` into `sh`; both now install a pinned v1.64.8.

**`optional: true` for components**, and `platform` and `app` components in scaffolded Go
projects.

**Build-provenance attestations** for release archives built by the release workflow:
`gh attestation verify <archive> --repo diktahq/verikt`. GitHub Actions does not currently
run for this repository, so a release built locally carries none.

### Fixed

**The install script works, fails closed and uses HTTPS only.** It requested an archive name
releases never published. A missing checksum entry, a mismatched hash or no hash tool now
stops the install; with no hash tool, the old script compared the expected hash against
itself. Every request is pinned to HTTPS and TLS 1.2, redirects included.

**The Claude Code hooks report what they find.** The check hook forced the exit code to 0 and
never reported a violation; it also missed every finding in a file the agent had just created,
because `git diff` never lists untracked files. It now names proxy rules that could not run,
and the session-start hook says when regenerating the guide fails. The refresh hook works on
macOS, and `.claude/settings.json` is merged without clobbering your hooks or a file verikt
cannot parse.

**A cached engine is verified against its embedded SHA-256** before it runs. A cache directory that is a
symlink, writable by others or owned by another user is refused.

**Waivers and grep rules report correctly.** Inline and override waivers are reported
together, a grep rule with a regex the engine cannot compile is invalid instead of silently
skipping that check, and `cmd_allowlist` is no longer hidden by `//go:build !ignore`.

**Scaffolds compile and pass their own check.** `dynamodb`, `feature-flags`, `multi-tenancy`
and `s3` scaffold again. `verikt add` puts files where the project's architecture puts them,
instead of hexagonal paths. Handler-package capabilities compile in clean, layered and flat
projects; clean and layered projects with `http-api` have one router; capability order no
longer breaks the build; `ddd` with `event-bus`, and `graphql` with `templ`, no longer
overwrite each other's files; and generated Go is gofmt-clean as written.
`mise run release-check` now builds and vets scaffolds across every architecture.

**Streams outlive the request timeout.** SSE and WebSocket routes were cut off by the same
timeout as JSON routes. They now sit outside it and manage their own deadlines.

**The BFF gateway is race-free, bounded and wired.** `FanOut` raced when a call named an
unknown service, upstream bodies are capped at 1 MiB, and upstream error text is never
returned to the client.

**Feature flags are wired for Go, and `requires_features` is enforced.** `verikt new` and
`verikt add` stop before writing anything when a capability needs a feature the target Go
version lacks, and say how to target one that has it.

**The capability matrix covers all 65 Go capabilities**, up from 21 in the generated
`docs/PROJECT.md` table.

### Security

**Generated code is safer by default**, in new projects and with `verikt add`: tenants come
from verified auth, never `X-Tenant-ID`; oauth2 `state` is single use and bound to the
browser; CORS echoes only the exact matched origin; websocket caps messages at 64 KiB and
keys connections by a server-generated ID; sse rejects CR and LF in event names; bff does not
follow backend redirects; mailpit rejects CR and LF in headers. The release workflow is
read-only except for the publishing job.

### Changed

**One pass/fail rule for every finding.** Proxy rules and decision gates failed only on the
literal severity `error`. Detectors, anti-patterns, proxy rules and decision gates now share
one decision, and no existing run changes outcome.

**Three detectors re-measured on real repositories.** `context_background_in_handler` used to treat any package named
like `handler` or `api` as a handler. It now reports `context.Background()` only when a
named `*http.Request` or `context.Context` is in scope, in any package. `live_dot_claude_fixture`
now reports only what Claude Code loads from a nested directory: over 26 local repositories,
628 of 1,025 earlier findings were `.claude/` directories holding only `agents/` or
`commands/`. `silent_ci_swallow` and `mutable_install_url` read more shell and YAML shapes;
over 85 local repositories and 261 Go modules this added 10 findings and removed none.

**Scaffolded Go code and verikt itself use `go.yaml.in/yaml/v3`** instead of
`gopkg.in/yaml.v3`.

## v0.2.1 — 2026-08-15

A false-positive fix. **No configuration change is required, and nothing that passed 0.2.0
fails here** — `verikt check` reports strictly less.

### Fixed

**`global_mutable_state` no longer reports lookup tables.** An unexported package-level
variable that nothing writes to is not global mutable state. Go has no const map or const
slice, so `var x = map[K]V{...}` is the only way to express a table — reporting it named a
construct the language requires, and prescribed dependency injection, which makes a static
table worse.

On verikt's own codebase the check fired 22 times and 21 were tables nothing ever wrote to.
A detector wrong 21 times in 22 teaches you to skim the section it appears in.

Still reported: **exported** variables, whatever a single file shows, because another
package can write to them; and anything **mutated** — assignment, index assignment,
`delete`, or `append` assigned back.

The trade is deliberate. A table mutated from a sibling file in the same package is now
missed. Occasional misses do less harm than routine false positives.

### Added

**A restraint fixture** — code written the way a careful engineer writes it, where every
detector must stay silent. Any finding fails the build. Detection was already guarded, and
restraint was not, so a detector could grow louder indefinitely with no test objecting.

### Effect

On verikt's own repository: 23 anti-pattern findings to 1, and the survivor is real. If you
ratchet a finding count, re-measure — it will drop.

## v0.2.0 — 2026-08-15

Fixes an external audit of 0.1.0 and the parity gaps found while fixing it — cases where two
implementations of the same check disagreed and nothing detected it. **Read the breaking
changes before upgrading:** a pipeline can newly pass or newly fail without any change to
your code.

### Breaking

**`verikt check` requires the embedded engine for Go projects.** The Go duplicates of the
engine's analysis are deleted. Released binaries embed the engine, so this affects builds
from source that skipped the engine build.

**Only error severity fails the check.** Warnings no longer do. Gate on `.result` in the
JSON output rather than selecting on severity across `violations[]` and `anti_patterns[]` —
those two arrays hold detector findings only, so a gate built from them misses proxy-rule
violations, stale rules and decision gates:

```bash
verikt check --output json > verikt.json
jq -e '.result == "pass"' verikt.json
```

**Error-severity anti-patterns fail again**, including `sql_concatenation` and
`swallowed_error`. They were silently downgraded to warnings whenever the embedded engine
resolved. Fix them, or waive them with a required reason — `severity_overrides` now covers
anti-patterns, and waived findings stay visible in a `WAIVED` section without affecting the
exit code.

**A path verikt cannot read fails the check**, reported as `unreadable_path`. The tool
cannot vouch for what it did not read.

**`anti_patterns[]` uses lowercase JSON keys**, and the document carries `schema_version: 2`.
`violations[]`, `anti_patterns[]` and `waived[]` are always present and always arrays.

### Fixed

`--diff <ref>` reported nothing at all — the ref was read as a pathspec, so every finding
was filtered away and the check passed unconditionally. `--staged` now filters detector
findings, not just proxy rules.

Proxy rules ran against nothing under the default `--path .`. A rule that swept its scope
and found nothing is no longer reported as stale. `check.exclude` matches whole path
segments instead of substrings, so excluding `gen/**` no longer silences findings in
`internal/agent/`. Glob patterns with `**` anywhere in them work, and rule scopes and
`verikt.yaml` share one matcher.

Test files no longer produce dependency violations in TypeScript, symlinks are skipped
everywhere, `testdata/` is excluded, and the engine no longer reports findings against its
own fixtures.

The `platform` capability's config layer reads the environment: defaults, then the YAML
file, then environment variables. Credentials have no YAML key at all, so a secret written
into the committed config file is refused rather than quietly accepted.

Full detail, including every finding and the reasoning behind each fix, is in
[CHANGELOG.md](https://github.com/diktahq/verikt/blob/main/CHANGELOG.md).

## v0.1.0 — 2026-03-23

First public release of verikt. Previously developed as "archway" — renamed to verikt as part of the dikta platform.

### Go Language Provider

63 capabilities across 10 categories. 4 architecture patterns (hexagonal, layered, clean, flat).

Core commands: `verikt new` (scaffold), `verikt add` (add capabilities), `verikt check` (11 AST-based detectors), `verikt guide` (generate AI agent context for Claude Code, Cursor, Copilot, Windsurf).

Smart suggestions, capability warnings, feature-flag template engine, proxy rules, decision gates.

```bash
verikt new my-api --language go --arch hexagonal \
  --cap platform,bootstrap,http-api,postgres,docker --no-wizard
```

### TypeScript/Node.js Provider

39 capabilities across data, resilience, security, patterns, and infrastructure. Two architectures: hexagonal and flat. HTTP framework choice: Express, Fastify, or Hono.

```bash
verikt new my-ts-api --language typescript --arch hexagonal \
  --cap platform,bootstrap,http-api,postgres,docker --no-wizard
```

**ORM choice.** Data capabilities default to Prisma. Drizzle is available as a query-builder alternative:

```bash
verikt new my-api --language typescript --arch hexagonal \
  --cap platform,bootstrap,http-api,postgres --set OrmLibrary=drizzle --no-wizard
```

### Go Query Builders

Two capabilities for structured query building on top of pgx/database-sql:

- **squirrel** — fluent SQL construction with `QB()` factory for PostgreSQL-aware placeholders
- **sqlc** — compile `.sql` files to type-safe Go functions

### Rust Analysis Engine

Embedded Rust engine using tree-sitter for import graph analysis. Supports both Go and TypeScript via language-specific extractors. Communication via protobuf over stdin/stdout. Cross-compiled for darwin-arm64, darwin-amd64, linux-arm64, linux-amd64.

### Governance Checkpoint

`verikt guide` includes a governance checkpoint — an instruction block that tells agents to verify architecture rules before modifying files and re-check compliance after tool results.

Validated by [EXP-10](/experiments/exp-10/): variance eliminated (0.89 → 0.00), violations reduced 25% on greenfield builds.

### Onboarding

`verikt init` is the single entry point. Detects your project state:

- **Empty directory** → greenfield scaffold wizard (same quality as `verikt new`)
- **Existing code** → analyzes codebase, then offers: map existing or bubble context (strangler fig)

`/verikt:init` skill for Claude Code mirrors the CLI flow. `verikt setup` installs the skill globally, locally, or both.

### Node.js Version Support

Default Node version: **22** (Active LTS). Node 24 support adds version-gated features via `features.yaml`:

- `native_ts` — drops `tsx` dependency, uses `node --watch` for dev server
- `es2024` — tsconfig target set to ES2024

### Website

- About page, 3 agent-specific guide pages (Claude Code, Cursor, Copilot)
- Capability pages, architecture comparisons, glossary
- 10 experiments documenting architecture context effectiveness
- robots.txt, per-page OG meta, structured data

```bash
brew install diktahq/tap/verikt
```
