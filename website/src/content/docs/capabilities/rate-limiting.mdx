`rate-limiting` adds a token bucket rate limiter to your Go service as Chi middleware.

## What You Get

- Per-client-IP token bucket middleware: `RateLimiter(ctx, rps, burst, logger)`
- Per-endpoint configuration

The client IP is the TCP peer, or the IP recorded by chi's trusted `ClientIPFrom*` middleware when you run behind a proxy, so a spoofed `X-Forwarded-For` cannot buy a fresh bucket. At most 100,000 clients are tracked at once; past that, new clients get 429 until idle ones are swept. The sweep goroutine stops when `ctx` is cancelled.

## When to Use

Use `rate-limiting` on any public-facing API to prevent abuse, brute-force attacks, and runaway clients. Essential for authentication endpoints and any endpoint with significant compute cost.

## Requirements & Suggestions

**Requires:** [`http-api`](/capabilities/http-api/), and chi v5.5.0 or later for `middleware.GetClientIP`. A new project resolves a current chi; when you `verikt add rate-limiting` to a project that pins an older one, run `go get github.com/go-chi/chi/v5@latest` first.

## Add to Your Service

```bash
verikt new my-service --language go --cap http-api,rate-limiting
# or add to an existing service:
verikt add rate-limiting
```
