`oauth2` adds OAuth2 flow support to your Go service, handling token exchange and callback routing for both client credentials and authorization code flows.

## What You Get

- OAuth2 provider integration with token introspection middleware
- Token exchange
- `OAuth2Flow` with a `Login` handler that starts the authorization code flow and a `Callback` handler that completes it

`Login` binds a single-use `state` value to the browser with an `HttpOnly`, `Secure`, `SameSite=Lax` cookie. `Callback` accepts the provider's redirect only when the returned `state` matches that cookie, which stops login CSRF. The token response is sent with `Cache-Control: no-store`. Mount both handlers on your router; the callback path must match `RedirectURL`. Pending state lives in memory, so with more than one instance move it to shared storage.

## When to Use

Use `oauth2` when your service needs to act as an OAuth2 client (logging users in via Google, GitHub, or an identity provider) or serve as an authorization server for machine-to-machine flows.

## Requirements & Suggestions

**Requires:** [`http-api`](/capabilities/http-api/)

**Suggests:** [`auth-jwt`](/capabilities/auth-jwt/)

## Add to Your Service

```bash
verikt new my-service --language go --cap http-api,oauth2
# or add to an existing service:
verikt add oauth2
```
