`idempotency` adds idempotency key middleware to your Go service, making retried requests safe by detecting and short-circuiting duplicates.

## What You Get

- Idempotency middleware that replays a stored response only for the same caller, method, path and `Idempotency-Key`
- In-memory key storage with expiry, an entry cap, and a 1 MiB cap on each stored response
- Duplicate detection

`Idempotency(store, scope, logger)` takes a scope function that returns the verified principal for a request. A request with a key but no principal is refused with 401, so mount it after authentication. With `auth-jwt`, `IdempotencyScopeFromClaims` scopes keys to the verified JWT subject.

## When to Use

Use `idempotency` on any endpoint where duplicate execution causes problems — payments, order creation, webhook processing. When paired with `retry`, idempotency keys ensure retries don't produce duplicate side effects.

## Requirements & Suggestions

**Requires:** [`http-api`](/capabilities/http-api/)

**Suggests:** [`redis`](/capabilities/redis/)

## Add to Your Service

```bash
verikt new my-service --language go --cap http-api,idempotency
# or add to an existing service:
verikt add idempotency
```
