`websocket` adds real-time bidirectional communication to your Go service, built on top of `http-api`.

## What You Get

- `WSHub`, which upgrades connections, tracks them, and broadcasts to every connected client
- A `GET /ws` route on the http-api router
- Writes serialised per connection, as gorilla/websocket allows one concurrent writer

## Connection Deadlines

http-api gives every JSON route a request deadline and the server a write timeout. A WebSocket must outlive both, so `/ws` is registered outside the request-timeout group. Hijacking the connection also drops the server's deadlines, so the hub sets its own: each write must finish within 10 seconds, and a connection that stays silent for 60 seconds is closed. Clients that need longer quiet periods should send pings.

## Same-Origin by Default

The upgrader leaves `CheckOrigin` unset, so gorilla/websocket accepts only same-origin browser requests and clients that send no `Origin` header. Accepting every origin would let any site open a WebSocket with your users' cookies (cross-site WebSocket hijacking). If browsers on other origins need access, set `CheckOrigin` to check an explicit allow-list.

## When to Use

Use `websocket` for features that need persistent bidirectional connections: chat, live dashboards, collaborative editing, or any scenario where the server must push updates without client polling.

## Requirements & Suggestions

**Requires:** [`http-api`](/capabilities/http-api/)

## Add to Your Service

```bash
verikt new my-service --language go --cap http-api,websocket
# or add to an existing service:
verikt add websocket
```
