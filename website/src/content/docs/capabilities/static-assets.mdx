`static-assets` adds embedded static file serving to your Go service using Go's `embed.FS` for single-binary deployments.

## What You Get

- `StaticHandler()`, an `http.Handler` that serves the embedded files with a one-year `Cache-Control: public, max-age=31536000, immutable` header
- A `static/` directory next to the HTTP handler code (`adapter/httphandler/static/` in hexagonal, `internal/interface/handler/static/` in clean, `internal/handler/static/` in layered, `handler/static/` in flat), with `css/style.css` and an empty `js/`

The assets live beside the handler because `go:embed` cannot reach a parent directory. URLs map one-to-one onto that tree: mount the handler at `/static/` and `/static/css/style.css` serves `static/css/style.css`.

## When to Use

Use `static-assets` to serve CSS, JavaScript, images, or any static files directly from your Go binary. Embedding assets removes the need for a separate file server and simplifies deployment — one binary contains everything.

## Requirements & Suggestions

**Requires:** [`http-api`](/capabilities/http-api/)

**Suggests:** [`templ`](/capabilities/templ/)

## Add to Your Service

```bash
verikt new my-service --language go --cap http-api,static-assets
# or add to an existing service:
verikt add static-assets
```
